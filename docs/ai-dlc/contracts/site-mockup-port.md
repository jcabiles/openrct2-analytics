The port is feasible but is not a copy. Mockup 19 is a 3,376-line single file whose charts are hand-drawn SVG fed by a made-up JSON blob (M/mockup-19-rct-exact.html:1572-1949). ## 3. External assets and offline
- Loaded from the network: GSAP 3.12.5 and ScrollTrigger from cdnjs (M:1950-1951); Fraunces (600, 800) and Work Sans (400, 500, 700) from fonts.googleapis.com (M:5). No images or other CDNs. Outbound `https://` links (duckdb.org, github.com, observablehq.com, 11ty.dev, openai.com, anthropic.com, a personal site at vercel.app; M:916-917, 2694-2763) are anchors, not loads.
- The mockup already degrades without GSAP: `const HAS_GSAP = typeof window.gsap !== 'undefined'` (M:1961), `tweenA/tweenS/fadeIn` fall back to instant (1974-1975), and ScrollTrigger use is guarded (2411, 2549). `prefers-reduced-motion` is honoured (1959). The CSS font stacks already fall back to `system-ui` and Georgia (M:23, `--font`, `--font-d`).
- Vendored in the repo today: nothing committed under site/assets besides `favicon.svg` and `park-month-chart.mjs`. Eleventy copies `node_modules/d3/dist/d3.min.js` (d3 7.9.0, ISC, pulled in by Plot) and `@observablehq/plot` 0.6.17 (ISC) to `assets/vendor/` (W/site/eleventy.config.mjs, passthrough copy). package.json devDependencies: @11ty/eleventy 3.1.6, @observablehq/plot 0.6.17, @openrct2/types 0.5.5, typescript 5.9.3. No GSAP, no font package, no chart library beyond Plot (and d3 transitively). ADR 0021 requires every browser library self-hosted from the locked node_modules, "never a CDN".
- Options: (A) Drop GSAP, use system fonts. Needs no new dependency and no approval; the mockup's guards make this the lowest-risk path; cost: loses the morph and scroll-trigger animations and the Fraunces/Work Sans look (system serif/sans stand in). (B) Vendor GSAP and fonts. Needs a new dependency in package.json and package-lock.json (hotspot) and the project owner's approval (the roadmap says so). GSAP's licence is a custom "Standard no-charge" licence, not on the lockfile allowlist ADR 0021 mentions (4 off-list already recorded), so check it. Fonts via @fontsource packages (OFL) are also new dependencies, plus woff2 files copied by passthrough; gain: pixel-faithful look; cost: approval, lockfile churn, bigger site. (C) Mixed: system fonts now, animations kept only if GSAP approved. Recommended: A for this item, with the animation and font vendoring left as a follow-up the owner can approve. Gain: offline now with zero dependency change; cost: visible difference from the mockup the owner picked, which `verify: owner-later` will see.

## 5. Test seams and the "no illustrative values committed" rule
Seams: (a) `site:build` writes to any `--output` dir, so tests can build the real templates against a temp `_data` directory (the page check already takes `--served-dir`; tests/page_check_support.py builds fixtures and calls `page_check.main`). (b) The data layer: if all `_data` reads go through one Eleventy global-data file or filter (for example `site/_data/` plus `site/figures.js`), a unit test can feed empty, partial and full files. (c) Pending placeholder: give it one class or `data-figure="pending"` attribute and one fixed text so the check can count it.
Proofs for "no illustrative values":
1. Fixture swap: build twice with two different synthetic `_data` sets (distinct numbers); every figure on the page must change with them, and no number outside the data and an allowlist of copy figures may appear. A page number not traceable to a file fails.
2. Empty build: build with `rows: []` everywhere; assert no digit sequence of 3+ outside allowlisted copy, every chart region shows the pending text, and the build still passes.
3. Grep the committed tree: forbid the strings `Illustrative data`, the invented second park identifier, and a stored fingerprint (hash) of the mockup's rows. Cheap and stable; cost: a negative list only catches known values.
4. A repo check that no `site/` file other than `_data/*.json` and an allowlisted copy file contains money-formatted or other numerals in a data attribute or script constant; the page_check already compares embedded JSON with the served files, extend the same pattern to each new data-driven region.
Copy figures (54.7 minutes, 67 of 67, 1,938 guests, 68 game days): these are cited facts, not illustrative, but the rule in the roadmap ("reading every figure from site/_data/") means the spec must decide; recommended: keep them as draft copy only if each names its source doc, and list them in the allowlist so proof 1 stays strict. Gain: honest story text; cost: they are committed numbers that go stale.
Other project-rule seams: every chart header needs unit and clock (copy mockup's "unit" spans; page check pins the pattern "unit: ..."/"clock: ..." only for the existing section), samples named and "observational" (footer line M:1565 already says it).

## 6. Risks and open questions (each with a recommended answer)
1. Offline: GSAP and fonts (section 3). Recommend option A (drop GSAP, system fonts). Gain: no dependency approval, passes ADR 0021 as is. Cost: look differs from mockup; animated board-meeting stepping becomes instant.
2. The page check pins today's page and rejects `https:` hrefs. Recommend: keep the old tables, chart and pinned sentences inside the Insights/board section unchanged, drop outbound hyperlinks (render the URL as text or a `[link: ...]` placeholder, which the mockup already uses), and rewrite the "two parks" prose. Gain: no change to page_check or its 13 tests; cost: no clickable external links until the later publication step. Alternative: loosen the check to allow `https://` only on `<a>` with `rel="noopener"`, cost: touches page_check and tests.
3. Hand-drawn SVG chart code (about 1,400 script lines) versus Plot and d3 (already vendored). Recommend porting the mockup's SVG drawing code as the mockup is the design, split into modules under 500 lines each; cost: more code to keep; gain: exact match with the picked mockup. Plot would be less code but would not match chart styles. Note `_check_chart_module` forbids `querySelector` in the existing chart module only; new modules need their own rule, so scope the check to that file.
4. Two-park design versus one-park sample: with one park the Park 2 series, stacked bars and park filter are empty. Recommend showing the pending placeholder for Park 2, never a made-up series, and deriving park labels from the data (Park 1 = first park id by order). Open point for the owner: park display names (the export carries only park_id).
5. Pending placeholder wording and look: recommend one fixed text "figure pending" in the chart box with the unit and clock line kept. Gain: matches the roadmap and design check 2 ("show an empty, labelled slot"); cost: the dashboards look sparse until the department-figures item lands.
6. Colour tokens in one place: the mockup has 90+ tokens in `:root` (M:9-40) plus the palette block (850-872) plus per-element hex in the scene and SVG. Recommend a single `site/assets/tokens.css` holding the five seeds and the derived tokens, with the scene/diagram hexes moved into tokens, and a check (grep for `#[0-9A-Fa-f]{3,8}` outside tokens.css) to prove it. Cost: a decent amount of hand edits; the grep may need an allowlist for SVG icon paths.
7. Dark mode: the mockup keeps a dark block; recommend dropping it from the port (the design doc says dark is not designed) or pinning light. Cost of keeping: untested colours on a public page.
8. Desktop only and 500-line limit: confirm no responsive rules need porting; media queries for phone can be dropped (roadmap: "Not in this item: the phone layout").
9. Hotspots: only if option B is chosen do package.json and package-lock.json change; otherwise the Makefile is untouched, since `site:build` and `site-export` already exist. `site/exports.toml` should not change in this item (new exports belong to the department-figures item); if the spec adds columns, `make site-export` and the committed `_data` must be regenerated together or `export check` fails.
10. Project rules: the mockup contains the made-up park id and no RCT files or screenshots, but the hero scene is hand-drawn SVG (fine). Do not copy `mockups/` into the repo; copy markup only. Private-path strings: none seen in the mockup (grep for /Users not run on all 3,376 lines; the spec should add a check).
11. Verification: `verify: owner-later` (the owner opens the built site), so the agent-checkable done line is: `make check` passes, plus the new empty-data and fixture-swap builds above.
