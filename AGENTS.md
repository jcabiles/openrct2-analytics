# AGENTS.md

Rules for every coding agent in this repo (Claude Code, Codex, Gemini). Claude also reads
`CLAUDE.md`, which imports this file. The shared rules in `~/.claude/AGENTS.md` apply too; this
file adds the repo's specifics and how to work a ticket.

- **Check command:** `make check` (Python environment check, format, lint, tests, plugin build and
  tests, contract and dbt checks on the sample, site build, SQL lint and secret scan; about 20
  minutes). Run it before you stop; a red or unrun check means the work is not done.
- **Tickets for agents** are in `docs/ai-dlc/agent-tickets.md`. Take one at a time, in its own
  worktree. Roadmap items not listed there are not ready for agents.
- **Never push, merge or check a ticket box.** A reviewer re-runs the check and records the
  review; only then can the branch be pushed.

## What this is

A portfolio analytics stack for a theme park run as a business. The project owner plays OpenRCT2 0.5.6; a TypeScript
plugin compiled to ES5 streams game events over localhost TCP to a Python listener. Raw events land as dated
JSONL files (the Pub/Sub topic stand-in), are split into Parquet per event type, checked against ODCS data
contracts, and modeled with dbt on DuckDB.

**Read `docs/CONVENTIONS.md` before writing code.** Its written rules outrank golden examples. The
architecture map is `ARCHITECTURE.md`. ai-org state: `docs/ai-dlc/profile.md`. House standards:
`~/.claude/rules/engineering-standards.md` applies in full.

## Commands

The virtualenv is `.venv` and `node_modules` is at the repo root, both in the main checkout; `make ticket` links them into a ticket worktree (gitignored). `make check` takes about 20 minutes. In a sandbox, set `UV_CACHE_DIR` to a folder under `$TMPDIR`.

- `make ticket ID=<id>` — claim an agent ticket: creates the worktree `.worktrees/<id>` on branch `ticket/<id>` from `develop` (`BASE=<branch>` overrides) and links the main checkout's `.venv` and `node_modules` into it, so `make check` runs there. A ticket whose branch exists is already claimed.
- `make setup` — Python env (uv), Node packages (npm ci --ignore-scripts), the `warehouse/dev/` folder, and the git hook. Run `git init` first in a fresh clone. It ends with `make doctor`.
- `make doctor` — check the Python environment without syncing it: `.venv` uses a Python inside uv's managed folder (skipped, with a note, when `uv` is not on PATH), every file listed in each installed package's RECORD exists, `bin/dbt` is executable, and the venv's own Python imports `dbt` and this project. It works offline and in the agent sandbox, prints a per-package summary with at most five missing paths each, and reports a file it cannot read as a note, not damage. On failure it prints the repair, `rm -rf .venv && make setup`; `uv sync` alone cannot repair stale install records. `pyproject.toml` pins `python-preference = "only-managed"`, so every `uv sync` uses uv's managed Python.
- **If Python breaks, run `make doctor` first.** Symptoms: `ModuleNotFoundError` or `ImportError` for an installed package or for `openrct2_analytics`, `dbt` missing or not executable, or tests that fail to start inside `.venv`. If doctor reports the environment whole, the `.venv` is not the cause; look at the code. `uv sync` or `pip install` does not repair damage that doctor finds (a plain `uv sync` after a `pyproject.toml` or `uv.lock` change is still correct). In a worker copy (a clone or worktree made for your own task), run the repair doctor prints, `rm -rf .venv && make setup`, which needs the network; in the main checkout, stop and report the doctor output instead, because only the project owner repairs the main checkout's `.venv`.
- `make check` — the gate: the Python environment check (`make doctor`), format, lint, file sizes, docs, absolute local paths (`scripts/check_local_paths.py`), the metric catalog rules, types, tests, plugin build, plugin tests, the contract check on the committed sample, the registry feed check on the committed sample, the save-file record check on the committed sample, the play-mode label feed check on the committed sample, the dbt source drift check, the dbt house rules, the contract breaking-change check (runs only while CI is set), the metric catalog shape check (dbt parse of the catalog), dbt parse and build on the sample, the showcase export comparison, the site build and the page check on that build, then a second dbt build on a zero-row extract, the built-columns check (each built model's columns match its YAML; no `_tenths` column outside staging), the dbt docs build, the exposure check, the cleaning-rule counts check (every known cleaning filter has a counts row), and the SQL lint (`sqlfluff`), all on the `ci` target in a temporary folder that is removed afterwards (the gate leaves no warehouse behind), secret scan. It ignores `DATA_SET`.
- `.venv/bin/python -m pytest tests/<file>.py` — run one test file while working on a ticket; it works offline. `make check` stays the gate.
- `make site-export` — rebuild the sample warehouse in a temporary folder and rewrite the served JSON files in `site/_data/` from its marts; the temporary folder is removed afterwards. Run it after a mart, allowlist or sample change, then commit the files; `make check` compares them with a fresh build.
- `make fix` — auto-fix formatting and lint issues.
- `make lock` — regenerate `uv.lock`.
- `make listen DATA_SET=<rehearsal|company>` — run the TCP listener that appends game events to `data/<set>/raw/`. Every capture, pipeline, publish and rollback command takes `DATA_SET` on the command line and refuses without it; an exported `DATA_SET` is refused.
- `make convert DATA_SET=<set>` — convert the raw JSON Lines into Parquet under `data/<set>/parquet/` and write the `seq` audit; exits non-zero when any session's `seq` has a gap, a repeat, or a first value other than 1, or when one session carries more than one `park_id`.
- `make contracts DATA_SET=<set>` — check the converted Parquet of one data set against the data contracts, then check the registry feed of that data set, then its save-file records, then its play-mode label feed.
- `make transform DATA_SET=<set>` — build the dbt models over one data set's converted Parquet into the development warehouse, `warehouse/dev/dev.duckdb`, after checking that data set's registry feed and play-mode label feed.
- `make pipeline DATA_SET=<set>` — run the after-play steps in order (`make convert`, `make contracts`, `make transform`), stopping at the first failure.
- `make capture-data DATA_SET=<set>` — capture one play session: build and install the plugin into the player's OpenRCT2 plugin folder, listen until the game quits, remove the plugin, convert the capture and print a report; a background watcher records each `.park` file created or changed in the save folders under `data/<set>/save_files/`, and the report pairs every save event with one such file; never runs the contract check or dbt; after a healthy `company` run it also writes the dated backup copies described under `make play`. The module `python -m openrct2_analytics.ingest.capture` exits 0 clean, 1 capture problem, 2 refused, 130 interrupted; through `make` any failure is make's own non-zero code.
- `make play DATA_SET=<set>` — the same capture as `make capture-data`, but the command opens the game itself (`open -a OpenRCT2`) right after the plugin is installed and exits 1 when the game is not seen running within 60 seconds (the limit runs only while the game check clearly says not running and no event landed; a game seen after a timeout gets a loud "NOT recording" line). Before the game opens it warns about any save file that changed while nothing was recording, naming the backup to load. After a healthy `company` run (both commands) it copies each park's last recorded save to the game's save folder as `<park name>-last-plugin-save-YYYY-MM-DD.park` and to a never-overwritten archive under `local/park-backups/` (`OPENRCT2_BACKUP_DIR`); the dated copy is replaced only while its bytes equal one of that park's archive copies, otherwise a copy with `-HHMMSS` added goes beside it; a failed copy exits 1 with "The recorded data is fine; only the backup copy failed." (ADR 0048).
- `make launcher` — build the "OpenRCT2 Enterprise" app in `~/Applications` (macOS only; never committed). It opens `launcher/play-company.command` in Terminal, in the checkout the app was built from; rebuild it after moving the repo. After the direnv checks it runs `make unfiled DATA_SET=company`; when that prints play waiting, the window shows the list and, when the first line is `offer` or `offer-after-convert`, asks "File the waiting play now, before this play?" (1 Yes, 2 No; any other answer asks again; end of input prints "No answer was read. Nothing was changed." and exits 130). Yes first runs `make convert DATA_SET=company` for `offer-after-convert` (its exit code is ignored; `make unfiled` is read again and the play is filed only when it now says `offer`, otherwise the window prints "The waiting play was not filed."), then `make auto-file DATA_SET=company RECORD=yes` and `make auto-file DATA_SET=company COUNT_AS=company`, which asks about each unregistered park by its label (`make unfiled` describes it); a failure prints "The waiting play was not filed (see above)." and then `Any rerun command above is not needed: the waiting play is offered again the next time this app starts` (the `To file it, run` line prints only after some failures, and no rerun command is needed), and the window goes on to the question. No goes on to the question at once; `no-offer`, or a failed check ("Waiting play could not be checked (see above)."), only prints and goes on. Then it asks "Where should this play count?" (1 Company, 2 Sandbox, 3 "Run autopilot on a finished park"; any other answer asks again; end of input prints "No answer was read. Nothing was changed." and exits 130). Answer 3 reads the park list once from `make autopilot-parks DATA_SET=company`, through `python -m openrct2_analytics.ingest.autopilot_menu` (tab-separated lines; it writes no file), and shows the parks without a `source_problem` as a numbered list, each by its `park_label` (field 2 of the helper's line; the helper refuses a park entry whose `park_label` is missing, not a string or only spaces, exit 1); a park with a source problem is printed as "Not ready: <label>: <reason>" and cannot be chosen, and `0` goes back to the first question (a list that cannot be read, no registered company park, or no ready park prints why and also returns to it). On a park's first run (`needs_ready`) it prints "This is the first autopilot run for <label>.", then the `READY` phrase (ADR 0049, which still holds the park ID) and reads what is typed (`READY=<typed>`; `make autopilot-year` refuses a wrong sentence); then it starts the dashboard if needed, runs `make auto-file DATA_SET=company RECORD=yes` (a failure prints "Autopilot did not start; see the messages above." and starts nothing), prints that the run can take up to about two hours and that the window must stay open, and runs `make autopilot-year DATA_SET=company PARK=<id>` under `caffeinate -i` (it keeps the Mac from idle sleep, not from lid sleep). When that exits 0 it runs `make auto-file DATA_SET=company COUNT_AS=company` and, once that exits 0, opens the dashboard. When the year does not finish it prints that not every step finished and says what to do next (choose 3 again when the messages say nothing was written or company data was not touched, or make stopped with a line starting with `***`; otherwise, because the year may have landed and unless they name a seq problem, do not choose 3 again, and file with the printed `make auto-file DATA_SET=company COUNT_AS=company` line); when filing fails it prints the same `make auto-file` line as the one to run by hand. Both lines say that command files every waiting park and may ask about others by their labels. For answers 1 and 2 it starts `make dashboard DATA_SET=company` in the background when nothing answers on port 8780 (under `nohup`, logging to `local/dashboard/server.log`), runs `make auto-file DATA_SET=company RECORD=yes`, and, only when that succeeds, `make play DATA_SET=company` (when the record step fails the game is not opened). After `make play` exits 0 it runs `make auto-file DATA_SET=company COUNT_AS=<company|practice>`, with `practice` the stored value for Sandbox, and once that exits 0 opens the dashboard in the browser. After any other exit of the play it prints `This play was not filed. If the report above names a seq problem, do not file it; otherwise run: make auto-file DATA_SET=company COUNT_AS=<the choice>`, because `make` reports every failed recipe as exit 2, so the capture's own code cannot be told apart. The window's exit status is that of the last play or filing step (for answer 3, the year or its filing), set before the dashboard opens. `make check` does not run it.
- `make capture-rehearsal DATA_SET=rehearsal` — play the nine-session, two-park rehearsal chain headless, prove it in the work folder, then land the raw capture and the park registry delivery into `data/rehearsal/`; needs the game, the benchmark settings and `OPENRCT2_REHEARSAL_PARK2`, and writes nothing outside the work folder and `data/rehearsal/` apart from the plugin build output. `DATA_SET` must be `rehearsal`. It refuses (before writing anything) when a setting is missing; a source save does not match its expected SHA-1 prefix; the work folder or data folder overlaps a protected folder; `data/rehearsal/raw/` or `data/rehearsal/registry/v1/` already holds files; the work folder already holds a folder from an earlier run; a `parquet.lock` is present; the game is running, cannot be checked (the module's `--skip-process-check` option skips the process-list check, so a game left open with no autosave in the last ten minutes goes undetected; `make` does not pass it), or saved in the last ten minutes; a port is busy; the one-minute load average stays at or above 3.0 for five minutes; a landing folder aliases another or resolves (links followed) into a protected folder (`plugin/src/`, `data/rehearsal/parquet/`, `data/sample/`, `data/company/`, the player's OpenRCT2 folder or a source save's folder); the game binary does not answer `--version`; or the plugin does not build. The same folder check runs again just before landing, before any landing folder or lock file is created, and once more under the landing lock; a refusal there exits 1, creates nothing in the protected folder, and keeps the captured files in the work folder. The module `python -m openrct2_analytics.ingest.rehearsal_capture` exits 0 landed, 1 capture or landing problem, 2 refused, 130 interrupted; through `make` any failure is make's own non-zero code.
- `make publish DATA_SET=<set>` — build one data set's warehouse into a candidate file, audit it, and swap it in read-only as `warehouse/<set>.duckdb`, keeping the replaced file for one rollback. The module `python -m openrct2_analytics.ingest.publish` exits 0 published and prints `published warehouse/<set>.duckdb: <T> tables, <R> rows; kept <file> for one rollback` (or `no earlier file kept`) as its last line, 1 failed, 2 refused, 130 interrupted; through `make` any failure is make's own non-zero code. A lock left by a killed run is removed by hand (`ARCHITECTURE.md`, "Environments and publishing").
- `make register-parks DATA_SET=<set> [PRACTICE=yes | PARKS="<id>:company,<id>:practice"] [START_YEAR=<year>]` — write the park registry delivery for every captured park of that data set that the registry does not list yet (company start year 2000 for the first company park and for sandbox parks; `PRACTICE=yes` (or `:practice` in `PARKS`; `practice` is shown as Sandbox) adds the note "Throwaway practice park; not company data."; `PARKS` registers only the listed parks, each with its own choice, refuses a listed park that is not waiting to register, and refuses being given with `PRACTICE`); run it after `make convert` and before `make pipeline`. `START_YEAR=<year>` (digits only; blank means not given) sets the company start year of the one non-sandbox park a run registers (ADR 0050): it is required once a non-sandbox company park is registered, and the only year accepted is the company year after the latest year the registered company parks hold (Park 1's last managed year Y refuses Y and accepts Y + 1; a registered park with no managed day yet holds its start year); a park that began in a game year other than 1 is refused whenever a year is typed or a company park is already registered (the first company park registered without `START_YEAR` is not checked for its origin); the first company park accepts only 2000, and a sandbox park takes none. If Y looks too high because play was abandoned after the closing 1 March, ADR 0050 explains it. A mistyped year that landed is fixed only by hand with `make delete-company-data` before go-live. Besides the refusals above, it refuses (exit 2, nothing changed) `START_YEAR` that is not digits, with `PRACTICE=yes`, or when every park to register is a sandbox park; more than one non-sandbox park in a run (with or without `START_YEAR`; `make auto-file` files several company parks by one run of this registration per park, ADR 0055); a missing, overlapping or too-late year (the text names the year to give); and, when a company park is already registered and a non-sandbox park is being registered, a company raw file holding a session that was never converted. It checks the year again under the landing lock. It refuses `DATA_SET=rehearsal` (ADR 0038); the Makefile refuses an exported `START_YEAR` or one holding a dollar sign. A `START_YEAR` given when no park waits to register is not used: the command prints a line saying so and exits 0, unless it is not digits or comes with `PRACTICE=yes`, which are refused before any data is read. The module `python -m openrct2_analytics.ingest.register_parks` exits 0 written or nothing to do, 1 failed, 2 refused, 130 interrupted; through `make` any failure is make's own non-zero code.
- `make play-status DATA_SET=<set>` — print one JSON object for the after-play panel: the dev warehouse state (`ready`, `missing`, or `building` while a writer holds its lock) and every session in the converted Parquet that `staging.stg_session_start` of `warehouse/dev/dev.duckdb` does not hold yet, with each park's ID, name, registration and the base name of its last paired save file (or null); while `building`, every converted session is listed. It writes nothing, but holds DuckDB's read-only lock on `warehouse/dev/dev.duckdb` while it reads, so a `make transform` or `make after-play` build that opens the file then fails: run it on demand, never on a timer while a build runs. The module `python -m openrct2_analytics.ingest.play_status` exits 0 printed (standard output holds only the JSON), 1 failed, 2 refused, 130 interrupted, with messages on standard error; through `make` any failure is make's own non-zero code.
- `make unfiled DATA_SET=company` — print the company play waiting to be filed, per park, for the launcher. Play waits when the converted `session_start.parquet` holds a session that `staging.stg_session_start` of `warehouse/dev/dev.duckdb` does not (the missing warehouse holds none), when a session failed its `seq` audit and is not filed, or when the raw `events-*.jsonl` files hold a session never converted. Standard output is empty when the check ran, nothing waits and no raw file with an unreadable line is listed. Otherwise line 1 is a status word and the rest is for the player: `offer` (filing may be offered), `offer-after-convert` (the same, but a recording was never converted, so accepting converts first) or `no-offer`, then "Play waiting to be filed:" and one line per park and kind (converted sessions not filed, recordings never converted, each failed session by ID), each starting `- <label>: ` (ADR 0058). The park label, built only in `park_label.py`, is `<name> (first played <Mon D>)`: "first played" is a wall-clock time, the plugin's `emitted_at` (stored in UTC) of the park's earliest `session_start` over the converted Parquet and the raw files together, converted to the local time zone of the machine that prints the label, and `<Mon D>` is the English three-letter month and the day without a leading zero in that zone. Parks that share a name and a shown day get `<name> (<Mon D>, <h:mm am|pm>)` and, when they also share the minute, the park ID is added after the time; a park with no first-played time is `<name> (<park ID>)`; a park with no name shows its ID in place of the name; a park the landing files say nothing about is its ID alone. The name is the latest `session_start` name (converted first, else raw). The label is read inside the same call as the list, so an unreadable Parquet or raw file exits 1 with `unfiled failed: io: <error>` on standard error and never shows a bare ID in its place. Nothing is offered while a session that failed its audit waits (`make after-play` files every waiting park and cannot skip one), nor while a recording is still live: a raw file changed in the last 2 minutes, the game running or its state unknown, or the landing lock present. A live recording that is the only thing waiting prints nothing at all, because its sessions are left out of the list. While the warehouse is being built it prints `no-offer` and "The warehouse is being built, so waiting play cannot be checked now." A raw file with a line that cannot be read is named by one line (unless the recording rule above hides it: changed in the last 2 minutes, the game running or its state unknown, or the landing lock present; a hidden file is not named and does not by itself print anything), but a line that cannot be read adds no session, so it is not listed by session. The line is `- Recording <file> has a line that cannot be read; make convert DATA_SET=company names it`; such a file also withholds the offer (reason `unreadable`, after `failed` and before `recording`), with the line "Nothing is offered while a recording has a line that cannot be read, because converting stops at it." It writes nothing, but holds DuckDB's read-only lock on `warehouse/dev/dev.duckdb` only while it reads, as `make play-status` does, so a `make transform` or `make after-play` build that opens the file then fails: run it on demand, never on a timer while a build runs. It refuses (exit 2) a data set other than `company`. The module `python -m openrct2_analytics.ingest.unfiled` exits 0 printed, 1 failed, 2 refused, 130 interrupted, with messages on standard error; through `make` any failure is make's own non-zero code.
- `make after-play DATA_SET=company [PARKS="<id>:company,<id>:practice"] [START_YEAR=<year>]` — run the after-play steps in order: register the waiting parks not yet registered (as `make register-parks` with `PARKS` and `START_YEAR`), `make contracts`, `make transform`, then print `make results`; stops at the first failing step and prints the step and the command to rerun the whole chain (no state file; registered parks are skipped on a rerun). Never publishes. It refuses (before any step) `DATA_SET=rehearsal`, a present landing lock, a dev warehouse being built, a session that failed its `seq` audit and waits unfiled (`seq-failed`: the text names each such session and its parks, says nothing is filed while one waits, and gives the preview `make delete-company-data SESSION=<id>`, which deletes nothing), a waiting park missing from `PARKS` (so with two waiting company parks it cannot register only one: it refuses a list that omits the other, and a list naming both as company is refused as several company parks; register one with `make register-parks PARKS=...` first, or file the play with `make auto-file`, which registers them one at a time before it calls after-play; ADR 0055), a listed park that is neither waiting nor registered, or one already registered with the other choice; `START_YEAR` is checked by the same rules as `make register-parks` before any step (a malformed value is refused even when nothing waits; the other start-year refusals apply to the parks it is about to register), and the rerun line repeats it; with no waiting park to register it prints `after-play: register: no waiting park needs registering; START_YEAR=<S> not used` and runs the other steps; an empty `PARKS=` means no list; the Makefile refuses an exported `PARKS` or `START_YEAR`, or one holding a dollar sign. The module `python -m openrct2_analytics.ingest.after_play` exits 0 every step passed, 1 a step failed, 2 refused, 130 interrupted; through `make` any failure is make's own non-zero code.
- `make auto-file DATA_SET=company (RECORD=yes | COUNT_AS=<company|practice>)` — file the company play just finished, in one of two modes (ADR 0051). `RECORD=yes` writes the sorted IDs of every converted session (`session_start` in the converted Parquet; none without the file) and of every session in the raw `events-*.jsonl` files, so a capture stopped before converting is later asked about rather than counted as the next play's, to the git-ignored `local/auto-file/converted-before.json`, replacing any earlier file, and exits 0; the launcher runs it before a play. `COUNT_AS` (`practice` is shown as Sandbox) is run after the play. Every question and line that names a park (the earlier-play, conflict and new-park questions, the "is new" and "already registered by this run" lines, the "Don't file now was chosen for park" text and the order refusals) shows the park's label, described under `make unfiled`; the typed commands and the "To file it, run" and rerun lines hold no label; the "<name> joins the company as Park <n>, ..." line and the "park number could not be shown for <names>" line keep the bare park name. The labels are read once per run, in the classifying step before any question or registration; when that read fails (an unreadable Parquet or raw file) the run exits 1 with `auto-file failed: io: <error>.`, and no bare ID stands in. It classifies each waiting park once: a park with a waiting session missing from the record file is this play's park and takes `COUNT_AS` when it is the only new park; with two or more new parks (ADR 0055) each is asked, whatever `COUNT_AS` is, with the question "Park <label>, <n> game days played, is new in this play. Which is it?" ("1 game day" for one day) and the options "Opened first", "Opened second", ... or "Sandbox", and an "Opened n" that does not match the order of the parks' first recorded sessions (Sandbox parks counted) is refused with the reason `order`; an already registered park keeps its registration, and is asked about only when it is this play's park and was registered with the other choice (answers: file it as saved, or not now); any other unregistered park is asked about by its label (Company, Sandbox or "Don't file now"). Without a usable record file no park is this play's, so every unregistered park is asked about and a line says why. For each park about to be registered it prints one line (`auto-file: park <label> is new; registering it as <company park, start year <Y>|a sandbox park>.`). With one company park to register it runs the after-play steps (the after-play module, in the same process) with `PARKS` (and `START_YEAR` when a company park registers after the first, taken from `start_year.next_start_year`). With two or more company parks it first plans every company park's start year in the order of the parks' first recorded sessions and runs every refusal check for all of them (the registry feed, a park of another data set, a staged delivery left over, a company raw file holding a session never converted, a typed year's game-year origin, the free delivery names, and a waiting list that changed during the questions), then registers the parks one at a time (one delivery each, each year checked again under the landing lock; the first company park takes no year, 2000), then runs the after-play steps once. It returns after-play's exit code, except that once a registration has landed a non-zero code other than 130 is returned as 1, with the lines that name the parks already filed and the rerun command after after-play's own lines; before any registration after-play's own refusal and rerun lines are what the player sees. The answers to the questions of a run (never a `COUNT_AS` choice or a kept registration) are stored in the git-ignored `local/auto-file/answers.json` just before the first registration (or the after-play call); a run that ends with no registration landed removes the file, so its rerun asks again, and one that landed a park keeps it, so the rerun asks nothing twice and keeps a registered park's stored choice without a conflict question; an unreadable file is ignored with one line, and the unregistered parks of this play are then asked about with the earlier-play question. A failure after a registration landed prints the failure, `auto-file: already registered by this run: park <label> as <how>[; ...].` and `To file the rest, run: make auto-file DATA_SET=company COUNT_AS=<x> (run it here; the launcher starts a new play)`, exits 1 (130 when interrupted), and never prints "Nothing was changed". The record file is removed after a successful after-play, before the closing lines print, so an interrupt while they print exits 130 after the cleanup (also when nothing is waiting, which prints `auto-file: nothing is waiting to be filed.`) and by `RECORD=yes`; the answers file is removed then too, and also when a run ends with no registration landed. Before the first registration it refuses (exit 2, "Nothing was changed") a data set other than `company`, neither or both modes, a `COUNT_AS` other than `company` or `practice`, the refusals of after-play that come before any step (`DATA_SET=rehearsal`, a present landing lock, a dev warehouse being built, a session that failed its `seq` audit and waits unfiled (`seq-failed`, as in after-play)), the answer "Don't file now" (the line `To file it, run: make auto-file DATA_SET=company COUNT_AS=<the choice>` follows), a question when standard input is not a terminal, and a company raw file holding a session never converted (refused by `start_year.next_start_year`); it exits 1 on an input or output error, on a staged delivery that fails the registry contract (`check-failed`), and 130 when interrupted or when input ends at a question; a taken landing lock (`lock-taken`) exits 2 with "Nothing was changed" before any registration landed and 1 after one. ## Never break

1. Every event carries `park_id`, `session_id`, `seq`, `event_id`, game date, and `emitted_at`; `seq` has no gaps or duplicates within a session. (From contract v1; the 2026-09-27 capture is schema 0.)
2. Raw captures are append-only; every fix happens downstream in dbt. The one exception: before go-live, `make delete-company-data` archives and then rewrites or removes company raw captures and registry deliveries (ADR 0033).
3. Money stays in the game's tenths of a dollar until one staging conversion; every metric names its unit and its clock (game day, company date, or wall-clock hour).
4. Build previews and client-side predictions never count as player actions.
5. Never commit RollerCoaster Tycoon files, game screenshots or video frames, the GPL type definitions, or private machine paths. Game footage lives on a video hosting site and the site links to it (ADR 0047).
6. The contract is versioned: adding fields is a minor bump; a breaking change is a major bump and a new landing path.
7. Analyses state their sample (parks, players) and say "observational" unless an experiment design backs a causal claim.
8. The plugin compiles to ES5 and stays within its measured per-tick cost budget.

## Working an agent ticket

**The ticket is the authority for the session.** Session-start checklists for roadmap work
elsewhere in this file or in `CLAUDE.md` do not apply to an agent ticket. Never read another
repo; if the ticket needs one, stop and say so.

1. **Pick.** Use the ticket your prompt names. Otherwise (Codex or Claude) take the first
   unchecked ticket in `docs/ai-dlc/agent-tickets.md` whose branch does not exist yet
   (`git branch --list 'ticket/*'`). If none is left, stop and say so. Gemini never picks: the
   caller names its ticket, claims it and starts Gemini inside `.worktrees/<id>`; started
   anywhere else, Gemini stops and says which ticket it would take.
2. **Claim it** from the repo root with `make ticket ID=<id>` (Codex asks the project owner's
   approval, because this writes to `.git`). It refuses a ticket whose branch already exists,
   which means another session has it. It branches from the local `develop` branch,
   which the caller keeps current; Codex has no network to fetch it.
3. **Work only inside `.worktrees/<id>`.** Start Codex from the repo root, then run every command, check and commit inside the worktree (`cd .worktrees/<id>` first); a commit made from the root lands on the default branch. `make ticket` links
   the main checkout's `.venv` and `node_modules` into the worktree; never install packages
   there, because Codex has no network.
4. **Write the failing test first.** Add a test that fails because of the bug, then fix the code,
   then confirm the test passes. Change only what the ticket needs. Gemini writes the test and
   the fix but cannot run them, and says so.
5. **Run `make check` inside the worktree** and report its last lines. Gemini cannot run it: say
   so, and the caller runs it.
   `make check` runs `uv run`, which tries to sync the environment and needs the network; Codex
   sets `UV_NO_SYNC=1` and `UV_CACHE_DIR` to a folder under `$TMPDIR`, and reports any step
   that still needs the network as blocked rather than skipping it.
6. **Commit** (Codex asks approval; Gemini never commits):
   - Subject: Conventional Commits (`fix:`, `test:`, `refactor:`, `docs:`, `chore:`),
     imperative, at most 50 characters. The body says why when it is not obvious.
   - End with the two trailer lines from the shared rules (`Agent-Vendor:`, `Agent-Model:`).
   - One logical change per commit; never commit work in progress.
7. **Stop and report:** the ticket, the commit hash and the check result (Gemini: the changed
   files and "check not run"), and anything left undone.
